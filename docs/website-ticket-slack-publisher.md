# Website-ticket Slack publisher

**Not deployed by this change.** Apply Alembic revisions from the live `82afe16026f6` through `0023`, `0024`, and `0025_website_ticket_slack_outbox` in order during an approved rollout. Do not run against production without checking the revision chain and the GitHub Actions secrets. Migration `0025` installs an empty outbox and a cutover timestamp. It does not backfill tickets; the existing `committee_dashboard` ticket and every `slack_actions_tickets` ticket remain unpublished. Later mutations of those tickets also do not enroll them. Evidence-suggested tickets are excluded: their transient manual origin is changed to `committee_agent_suggestion` in the same transaction, and the outbox entry is withdrawn before commit.

The hourly workflow keeps Slack archive synchronization but **does not** import Slack-origin tickets or repost legacy reminders. The independent `publish` job runs regardless of archive freshness (or archive failure). It needs `DATABASE_URL` with access to the private outbox (DB owner or service role) and `SLACK_BOT_TOKEN`. The bot must be in `C0BQPDP5T44` and have `chat:write` plus read permission for the channel (`conversations.history` and `conversations.replies`; the appropriate `channels:history` or `groups:history` scope). The root and replies use stable event markers for reconciliation. `WEBSITE_URL` defaults to `https://www.imperial-efds.com` and must be a trusted HTTPS origin.

A claimed event is committed as `sending` before POST. Successful posts record the Slack timestamp; root metadata and acknowledgement commit together. A lost response becomes `uncertain`: scheduled runs look for its marker, but **never resend when the marker is absent**. Stale `sending` claims also reconcile only. Earlier unresolved events block later events for that ticket. Inspect `ticket_slack_outbox` and the target Slack channel/thread when a job reports uncertainty; do not reset `uncertain` to `pending` unless the external outcome has been established independently. Definitive Slack API rejections and read failures are deferred with backoff. The current worker exits nonzero on deferred/uncertain work to surface problems in Actions.

Local checks, without live side effects: `PYTHONPATH=.:src pytest tests/test_ticket_slack_publisher.py -q`. The opt-in SQL integration test requires **a disposable local PostgreSQL database named `efds_test_*`**, specified only as `EFDS_TEST_DATABASE_URL`; it refuses non-loopback hosts and never reads `DATABASE_URL`.
